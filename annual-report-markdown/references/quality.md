# 质量体系：解析完成与内容可信分别报告（references/quality.md）

对应设计方案：§12 证据、§13 质量体系。

## 1. 五层检查

| 层次 | 检查内容 | 能证明的范围 |
|---|---|---|
| 运行与文件 | 页数、哈希、文件完整、任务完成或失败 | 程序处理过哪些输入 |
| 内容覆盖 | 检出对象去向、图像区域覆盖、缺表和重复检测 | 已知内容是否在处理时丢失；仍需防检测漏项 |
| 结构 | 阅读顺序、表头单元格关系、跨页连接、章节边界 | 内容之间的关系是否符合证据 |
| 文字与语义 | 原值、符号、期间、币种、主体、口径 | 一个值是否能被正确解释 |
| 财务一致性 | 合计、勾稽、跨表或跨期关系 | 已解释字段是否存在应调查的冲突 |

对关键数字的核对使用独立原文标注或视觉复核建立真值。**第二引擎与第一引擎一致只是一个信号**：它们可能共享模型或犯相同错误。

## 2. 财务校验必须先判断适用性

| 校验 | 适用前提与限制 |
|---|---|
| 资产 = 负债 + 权益 | 同主体、同日、同币种、同单位、同重述状态；允许与原列报精度相符的舍入差 |
| 利润总额 − 所得税 = 净利润 | 必须对应同一报表定义及范围；区分终止经营和其他单列项目 |
| 现金流变动与期初期末 | 必须包含报告列示的相关调节项，不能只固定拼三个净现金流 |
| 分项合计 | 仅适用于完整、互斥且声明覆盖总额的项目；“其中”常是不完全列举 |
| 分部合计 | 识别内部交易抵销、未分配项目、分部计量口径及调节表 |
| 跨表现金对照 | 财务状况表现金与现金流量表口径可能有调节，不能一律要求直接相等 |
| 同比重算 | 先确认期间与重述口径；基期为零、负数、固定汇率或报告另有定义时，不套通用公式 |
| 期初与上期期末 | 先识别重述、准则变更、合并范围变化；且仅在输入包含所需报告时执行 |

- 误差容忍来自各输入与合计的**列报精度**，用舍入区间求和判断，不默认设成任意 0.1% 或 1%。
- 校验结果包括：通过 / 未通过 / 不适用 / 条件不足，并保存实际输入与差额。
- 任何关系失配先形成问题，**不能反向修改金额来“配平”**。
- 关系全部通过，也不能证明没有整列对调、同期误配或单位整体错用。
- 反例：AIA 2024 年报现金流量表列有银行透支调节，不能与财务状况表现金做硬等式。

## 3. 证据粒度与来源（对应 §12）

每条可计算数据应能回答：

1. 原值在哪一页、哪个表格单元格、正文片段或图中标签？
2. 表格的行名列头，或正文的完整语句，或图表的系列和坐标轴在哪里？
3. 单位、期间、主体及重述状态从哪里取得？
4. 有哪些影响理解的脚注？
5. 哪个引擎识别，做过什么处理，因何选择该候选？

事实来源明确区分 `table_cell` / `text_span` / `figure_label`，三类来源采用同一套语义与质量门槛。不能为了统一格式把正文或图表数字虚构成表格单元格，也不能让它们绕过验证。

- 证据粒度分 page / region / table / cell / span；只有表级框就报告 table，不编造单元格坐标。
- 上下文不能唯一确认的数值不能被标成可计算。
- 证据可跨页：值在续页、表头与单位在前页、编制基础在另一章节——保存证据集合。
- 对正文合并、表格拼接、重复表头隐藏、单位换算、人工修正：记录输入对象、操作、输出对象与规则版本。
- 人工核对修正另存修订记录，保留旧候选；后续重跑不能抹掉人工决定。
- 建议提供轻量本地复核页：左侧原 PDF 区域，右侧识别表与字段上下文，直接显示冲突。第一版可生成可点击的静态复核页（`复核/index.html`）。

## 4. 对象状态与使用资格

对象状态：**已提取 / 待复核 / 按规则验收通过 / 解析失败**；另记是否人工核对。

使用资格拆开记录：

- `readable`：可以用于阅读，但保留对应警告。
- `traceable`：能够定位原 PDF，不表示转录或含义已正确。
- `citable`：引文文字、必要限定与上下文已按相应规则核对，可带证据引用。
- `computable`：文字、结构、上下文、单位和必要证据均满足规则。

规则示例：

- 错误 OCR 即使有准确页框也只满足**可定位**，不能作为公司原话引用。
- 未核实区域可作为待复核原图展示，**不给其文字转录授予可引用资格**。
- 表格可读 ≠ 所有单元格可计算。
- 文件可部分成功：已通过的表不被无关扫描页阻塞；但存在未解决的重要主表时，整份报告不能标为“财务结构化完整”。
- 引擎原始置信分与“文字/结构/语义/证据/计算”状态分别保存；不把模型分数解释成真实正确概率，将来只在代表性标注集上完成校准后才考虑概率阈值。

## 5. 复核队列（对应 §13.4）

按问题实际影响排序：关键主表及单位/期间冲突优先 → 高复用附注 → 正文重要限定 → 其他版面问题。

每条含：对象、原因、证据裁剪、候选、已试方法、下一步。

**有界升级**：主方法一次 → 必要时替代方法一次 → 仍冲突留待复核。允许为明确可恢复错误调整一次参数；不无限重跑，也不为“全部通过”持续调用大模型。

## 6. 已落地机制（V0.2 切片，2026-09-05）

以下把上文抽象条款固化为可运行实现（详见 SKILL.md 与各脚本）：

| 机制 | 实现 | 对应条款 |
|---|---|---|
| 表体数值核对 | `scripts/verify_tables.py`：把“显示网格”（优先人工重建 rows，否则 MinerU 候选正文行）逐行与源 PDF 同页 **pdfplumber 精确文字层** 比对（标签命中 + 行内数值词 x 升序前缀匹配）；输出 `索引/table_verify.json/.md`、`目检/table_check.json` | §13 真值核对、§13.3 使用资格、§18.3 原值/上下文 |
| 复核入口 | `scripts/build_eyeball.py` → `目检/index.html`：左原页图、右阅读顺序候选、下方表格候选 + 每表“数值核对 ✓/✗”状态 | §12 复核页、§15 复核/ |
| 人工修订层 | `目检/table_titles.json`（表题）、`目检/table_layout.json`（表头/版面/rows 重建），原始 `表格/table-*.json` 不动 | §12 修订记录保留旧候选、§13.4 复核队列 |
| 状态与资格 | 表格 `candidate_status=extracted`、`eligible_for_calculation=false`；quality `overall_state=partial` | §13.3 使用资格 |

**核对真值纪律**：单元格数值的真值一律取自 pdfplumber 精确文字层 + 词级 x 坐标（不要手抄 OCR）；“文字层核对一致”只证明单元格内容与原页文字一致，**不证明**期间/单位/主体归属正确，也不替代人工终核。
