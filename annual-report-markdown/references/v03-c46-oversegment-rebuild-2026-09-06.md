# V0.3-C4.6 有框线主表过切分 → 原生词 3 列重建（2026-09-06）

对应设计方案：§9.2/9.3 表格处理与复杂结构、§7.2 页面内结构、§13.1 文字与语义。

## 背景（C4.5b 暴露）

中国广核 2025 年报六张法定主表 0 facts：pdfplumber 把有框线表**过切成 9 列**，
主表 header 检测要求"恰好 3/4 列且 col0=项目" → 全部不成立。它不是坍缩（那条走
MinerU borderless），而是有框线被多检出竖线 → 看起来正常但列数虚高。

原生词核验（p94）：真实布局就是 **3 列**——标签 x≈56–100、期末余额表头 x≈274
（数值中心≈300）、期初余额表头 x≈434（数值中心≈460）；"货币资金"标签与数值
基线略错位（top 150 vs 153）。

## 实现

`financials.py` 新增 `_native_rebuild_oversegmented(doc, page)`：

- 触发：doc `column_count > 4`（过切分）才尝试。
- 值列锚点：优先用原生期间表头词（期末余额/期初余额/本期金额/上期金额…）的 x 中心；
  续页无重复表头时，把数值词 x 中心按最大间隔切成两组作为两值列。
- 行聚类：**y 重叠聚类**成视觉行（标签与数值基线可错位，不能按 top 取整）。
- 每视觉行生成 3 格：col0=标签（左侧非数值词）、col1/col2=按中心落到两值列。
- **保守门**：无数值词、两组不够分离（gap<60/跨度<80）、任一"值列"数值过宽
  （>130，疑似真多列）、行数<3 时一律返回 None → 调用方保持原 doc（零回归）。
- 接线：主表 docs 载入后逐个尝试重建；重建片段记入逻辑表
  `native_rebuild_fragments` 与 `reconstruction_method=native_xy_oversegment_v1`。

## 结果

- 广核：0 → **116 facts**（6 主表，5 张走 native_xy_oversegment_v1；合并利润表本就是
  干净网格未触发）。货币资金 fact=20,826,720,819.03（p94，与原文一致）。
- **无回退抽查**：茅台 469、伊利 515、北新 590 与基线完全一致（重建仅对 >4 列过切分
  片段触发，3/4 列正常网格不受影响）。
- 测试：新增 `tests/test_c46_oversegment.py`（3 项：3 列重建正确、正常网格不触发、
  锚点/数值不足返回 None）；全套 **86 项全绿**。
