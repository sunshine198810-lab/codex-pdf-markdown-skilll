# P0 引擎/几何选型实测（2026-09-05）

样本：茅台 600519（110 页，简体半年报）＋ 平安 601318（370 页）＋ 移动 600941（214 页），后两者为 A+H 年报。
工具：`scripts/p0_probe.py`（pdfplumber 0.11.10 / pypdf 6.16.2 / pdfminer.six，字符与词级坐标）。
本报告只记录“几何与证据层”实测，不构成对任何文字的“可引用/可计算”资格声明（见 `quality.md`）。

## 1. 一句话结论

> 在 3 份报告（茅台 110 / 移动 214 / 平安 370 页）上：**字符/词级坐标可靠、阅读顺序可重建、页眉页脚
> 可坐标分类、“合计”不误删、有框线表可检出**——V0.1 已确认的几类失败（倒序、`(0,0)` 聚合、双栏误判漏字、
> 页眉误删“合计”）在“pdfplumber 几何证据层”上均可避免或可定位。**pdfplumber/pdfminer 足以承担
> “几何证据层”与阅读顺序基础**；但保险/附注类无框线表（平安约 40%、移动约 17% 的高数字页）pdfplumber
> 检不出框线表，**表格结构恢复必须由 Docling / PP-StructureV3 / MinerU 承担**（见第 3 节）。

## 2. 结果

| 检查项 | 实测 | 结论 |
|---|---|---|
| 页数 | pdfplumber 读得 110 页 | 与 pypdf 一致 |
| `(0,0)` 坐标污染 | 页 2/5/8/26 `zero_coord=0` | 字符坐标真实可用；V0.1 的坐标塌缩不出现 |
| 页眉识别 | 顶栏候选仅 1 个：“贵州茅台酒股份有限公司2026年半年度报告”，110/110 页重复 | 可作页眉模板，按坐标分类即可 |
| “合计”误删风险 | 全书“合计”169 次，页眉/页脚 **0** 次 | 坐标分类不会把表内“合计”当页眉删除 |
| 第 2 页正文顺序 | “重要提示 → 一、→ 二、→ … 十一” `headings_order_ok=True` | 同页多节保留、顺序不颠倒 |
| 第 5 页指标页 | “七、主要会计数据和财务指标 → (一) 主要会计数据 → 单位：元 币种：人民币 → 本报告期比…” | 期间/单位/栏目可分离 |
| 第 8 页版式 | 正文+现金流量说明段落；右起始行仅 1 → 非双栏；无 ≥300 字符融合超长行 | V0.1“被误判双栏漏掉 1085 字符行”在几何层不复现 |
| 第 26 页财务报表 | 行项目与金额成对可读（结算备付金/拆出资金/交易性金融资产…） | 资产负债表行名+列金额是表格识别的正确输入 |
| 有框线表检出 | 高数字页（≥40 数字词）中无框线表页 = 0 页 | 本报告财务表基本有框线，pdfplumber 可检出 |

## 3. 跨报告扩展实测（同日 · 平安/移动，A+H）

在“茅台”之外追加两份 A+H 年报：平安 601318（370 页）、移动 600941（214 页），同款探针
`scripts/p0_probe.py --full`。茅台=110 页对照。

| 指标 | 茅台 | 移动 | 平安 |
|---|---|---|---|
| 页数 | 110 | 214 | 370 |
| 采样页 `zero_coord`（p2/p5…） | 0 | 0 | 0 |
| 页眉模板数（跨页重复 ≥3） | 1 | 1 | **12（章节型页眉）** |
| “合计”出现 / 页眉页脚中的 | 169 / 0 | 135 / 0 | 190 / 0 |
| 疑似无框线高数字页 | 0 / 110 (0%) | 37 / 214 (17%) | **147 / 370 (40%)** |
| 疑似双栏页 | 0 | 0 | 1（另有装饰镜像文字页） |
| 语言 | 全简体 | 简体+少量混排 | 简体为主 + 15 混排 + 2 英文页 |

### 抽样确认（无框线难点表为真，非误报）

- 平安 p14：`主要会计数据及财务指标`，表头 `2025/2024/较年初变动(%)/2023`×`12月31日`，行名
  `总资产` + 金额 `13,898,471 12,957,827 7.3 11,583,417` —— 多年对比财务主表，**pdfplumber 未检到框线表**。
- 移动 p126：`合并财务报表附注 · 三 税项（续）`，单位脚注“（除特别注明外，金额单位为人民币百万元）”，
  跨页续表、无框线 —— 典型附注结构表。

### 新发现的难点（A+H 特有）

1. **章节型页眉**：平安 12 个模板（业绩综述×21、风险管理×9、财务报表附注×82…）。页眉须“模板分组 +
   坐标分类”，不能假设单一模板；也不能凭“出现三次”删除。
2. **装饰/镜像文字**：平安 p5 出现 `们我于关`（=`关于我们` 水平镜像的装饰字，常与 `WHO WE ARE` 成对），
   属于版式设计而非提取乱码——应分类为装饰对象，**不能当作乱码去“修复”成倒序**。
3. **中英混排与英文页**：平安含 15 个混排页 + 2 个英文页；需要语言与“对应版本/平行文本”建模。
4. **无框线表是保险/附注报表的主形态**：移动 17%、平安 40% 的高数字页检不出框线表，pdfplumber
   的 ruled-line 表检测**不足以支撑主路线**。

### 对选型的决定性影响（量化后）

| 候选 | 在 3 份报告上的定位 |
|---|---|
| pdfplumber 几何证据 | 坐标/页眉/“合计”/顺序/有框线表——**验证可靠**，作证据层与阅读顺序基础 |
| pdfplumber 框线表识别 | 仅覆盖“茅台型”有框线表；保险/附注无框线表大量漏检（0% vs 17%/40%） |
| MinerU pipeline | **无框线表/多级表头结构候选（已验证，见 §5）**：主表数字正确、rowspan/colspan 保留；但须清理伪影、经统一结构 |
| Docling / PP-StructureV3 | 繁体/扫描及对照补充（本期未装未跑） |
| MinerU hybrid/vlm-engine | 更高精度候选；需另下大模型（未跑） |

## 5. MinerU 整页对照（2026-09-05，难点表页）

用本机 MinerU 3.4.5 `-b pipeline`（模型 PDF-Extract-Kit-1.0 已缓存 1.0G、MPS、约 10–20s/页）对
“无框线难点表”页做整页对照：

- 平安 p14–15（`主要会计数据及财务指标`）：**无框线主表被恢复为结构表，数字与原文一致**
  （总资产 `13,898,471 / 12,957,827 / 7.3 / 11,583,417` 等），多张逻辑子表（资产负债表型/利润表型/
  每股型/分季度/非经常性损益含“合计”）正确切分；表注“注：…”以正文保留。
- 移动 p126（附注`三 税项（续）`）：**多级表头保留** `rowspan=2`(公司名称)＋`colspan=2`(税率:2025/2024)，
  16 行子公司税率表完整、数值准确。
- 输出 schema（对齐设计）：`content_list` 块含 `bbox`、`page_idx`(0 起始)、`img_path`、
  `table_caption`(表题)、`table_footnote`(表注)、`table_body`(HTML)；块级坐标可做证据回查适配
  （正是设计 §7.1 MinerU 归一化坐标的例子）。
- 视觉化：每页同时产出 `_layout.pdf / _span.pdf / _origin.pdf`，利于人工复核。

### MinerU 的伪影（须由我们清理，不能当权威）

1. 复杂合并业务表（平安“其他主要业务数据和监管指标/综合金融”）会把**多级行名与合并列拍平**：
   如 `营运ROE(%) 营运利润` 合并进一格、`基本每股营运收益` 出现 `2.70 7.66` 挤在一格 —— 丢失合并结构与子组边界。
2. 单位/表题错位：`(人民币百万元) 综合金融` 被并入表头格；移动 p126 单位脚注“（除特别注明外…百万元）”
   被并进附注标题行。
3. 表结构伪影：多余空行、表尾漏入杂散 token（移动 p126 表尾多一个 `%`）、部分词被插入空格
   （“上升0.2个 百分点”）。
4. 关闭期 MPS/torch 偶发 `libc++abi: recursive_mutex lock failed` 噪音（任务已完成，仅析构期）。

### 对选型的结论（补充 §3）

- **MinerU pipeline 可承担“无框线表/多级表头结构候选”**：主表数字正确、移动附注表 rowspan/colspan 保留，
  强于 pdfplumber 的 ruled-table（后者对平安 40%/移动 17% 高数字页检不到表）。
- 但伪影说明：**不能把 MinerU 的 markdown/HTML 当权威中间层**；须进统一文档结构 + adapter 坐标换算 +
  财务约束与质量门（清理空行/杂散 token、还原合并、绑定表头/单位/期间）后再用。
- 综合 3 份报告实测，主引擎分工可定：
  pdfplumber=几何证据层/页眉/阅读顺序/有框线表；**MinerU pipeline=无框线表与多级表头结构候选**；
  Docling/PP-StructureV3 作为对照与繁体/扫描补充；扫描纯图页仍需 OCR 专用通道。

## 6. 局限（诚实记录）

- 样本 3 份均为简体 A 股（含 A+H 公司年报）原生 PDF；仍无**繁体港股、全英文年报、扫描/混合、银行独立报表**等样本。
- 页眉阈值按页高 6% 比例估计；个别标题页顶栏带会低于阈值（探针参数校准问题，不影响模板分组结论）。
- “无框线高数字页”用“数字词≥40 且 pdfplumber 无框线表”近似，是**候选信号**而非标注真值。
- MinerU 对照仅 3 个难点页（平安 p14–15、移动 p126），未做全书对照与表格单元格级精度测量；伪影清单基于目检。
- MinerU 仅跑了 `pipeline` 后端（用已缓存模型）；`hybrid/vlm-engine` 未跑（需另下大模型）。
- 阅读顺序按 top/x 启发式重建，未做“先识别区域再排序”的正式版面流程（V0.2）。

## 7. 下一步（P0 收尾 → V0.2）

1. 补齐样本：1 份繁体港股年报 + 1 份全英文 + 1 份扫描/混合（可选），跑同一探针确认坐标/页眉/语言结论是否外推。
2. （已完成部分）MinerU pipeline 对难点表页对照见第 5 节；如需进一步可跑 `hybrid-engine` 或对单元格精度做标注测量。
3. 主引擎分工（已由 3 报告 + MinerU 对照支持）：
   - 几何证据/页眉/阅读顺序/有框线表 → pdfplumber 几何层；
   - **无框线表、多级表头、跨页续表 → MinerU pipeline（已验证可行）**，Docling/PP-StructureV3 作对照与繁体/扫描补充；
   - 扫描纯图页 → OCR 专用通道（PP-StructureV3/OCR）。
4. 确认后在 `adapters` 实现 pdfplumber 证据 adapter 与 MinerU adapter（含 0 起始 page_idx / 归一化 bbox 换算），
   `layout` 实现“区域优先”的正式顺序流程，再进入 V0.2 最小研究包。

复现：`python3 scripts/p0_probe.py <pdf> --pages 2,5,8,26 --full`
