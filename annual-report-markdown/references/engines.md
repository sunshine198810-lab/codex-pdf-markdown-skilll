# 引擎选型：复用成熟能力，自建财报约束（references/engines.md）

对应设计方案：§7.1 坐标统一、§14 引擎选型。

## 1. 选型立场

- 建议先以 **Docling 标准管线**作为主干候选，搭配原生 PDF 几何/文字证据；**PP-StructureV3** 作为中文 OCR 与复杂表格候选补充；**MinerU** 作为对照方案。
- 最终主引擎由**真实年报测试**决定；第一版生产运行不要求三套模型同时常驻。
- 原生提取结果、布局模型结果与财务约束的融合由我们控制。**不要把任何工具输出的 Markdown 当成权威中间层**，也不要从其 Markdown 重新猜表格。

## 2. 候选与职责

| 候选 | 推荐职责 | 已知边界 |
|---|---|---|
| PDF 渲染器 + pdfplumber | 页面证据、字符与线条位置、原生表格候选 | 不自带 OCR，也不负责财务口径 |
| Docling 标准管线 | 版面、阅读顺序、表格、图片和结构化文档表示 | 需验证本机性能、繁体和复杂财报；每个单元格不保证都有细粒度坐标 |
| PP-StructureV3 | 中文扫描及复杂区域的 OCR、表格/版面候选 | 后端、模型和依赖需实测；通用榜单不能代替年报验收 |
| MinerU | 全流程对照，必要时替换主方法或处理困难页 | 输出需适配坐标、验证跨页关系；版本与许可须读所选版本 |
| PyMuPDF | 可选渲染、文字/表格提取通道 | 使用前确认 AGPL 或商业许可适用方式，不作为必须依赖 |

参考：pdfplumber（github.com/jsvine/pdfplumber）、Docling 文档模型、PP-StructureV3 输出说明、MinerU 官方仓库、PyMuPDF 文档与许可。

## 3. 坐标统一（对应 §7.1）

不同工具使用不同起点、单位与页号基数，必须通过 adapter 转换到统一工作坐标：

- `physical_page` 从 1 开始，与原 PDF 物理页一一对应。
- 工作坐标：旋转与裁切后的可见页面，左上角原点，单位 point。
- 保存原坐标→工作坐标、工作坐标→渲染像素的变换与 DPI；截图框能反算回原 PDF。
- 印刷页码另存 `printed_page_label`；一个物理页含两个印刷页时保存两个子区域。
- 例：MinerU 部分输出使用 0 起始 `page_idx` 与 0–1000 归一化 bbox，须经 adapter 换算。

pypdf 官方文档明确区分文本矩阵与页面变换，且提示复杂文档中的坐标定位限制；pypdf 本身不承担 OCR 与版面语义识别。问题出在用法与职责安排，不能据此判定 pypdf 对所有用途都不可用。坐标必须经过变换、旋转与原点统一后才能参与排序。

## 4. 运行环境与许可（Mac / 本地）

- 采用**独立运行环境**，登记 Python、引擎、模型、硬件后端与内存需求。
- 优先测试可运行的标准/CPU 管线，不假设所有 CUDA 或 MPS 配置都能直接使用；大批量吞吐待实测后再考虑其他计算设备。
- **默认本地处理**；下载模型与上传报告是两回事。Docling 提供离线模型路径与远程服务开关，采用**关闭远程服务**的默认配置。商业 OCR 或远程视觉模型仅作为明确配置的可选方式，并展示上传范围与费用依据。
- **固定依赖与模型版本**，记录代码与模型许可：Docling 代码 MIT、PaddleOCR 代码 Apache 2.0（模型另核）；MinerU 当前许可证含附加条款，实施时读取所选版本，不依赖旧版“AGPL”印象。

## 5. 适配与融合

- `adapters` 模块把各引擎原始输出转为统一对象结构（页、块、单元格、图片、坐标、来源）。
- 每项输出记录：引擎名、模型版本、配置、来源粒度、候选状态。
- 缓存键包含源哈希、区域、引擎/模型版本与配置；换模型不得误用旧结果。
- 引擎原始置信分与“文字/结构/语义/证据/计算”状态分别保存，不把模型分数解释为真实正确概率（见 quality.md）。

## 6. 诚实声明

引擎选型结论只有在代表性 A/H 样本（见 acceptance.md）上实测后才成立。P0 阶段的首要任务即：在本机跑通候选管线的标准/CPU 路径、评估困难页处理，再决定主引擎；**不先写大量指令再承认底层不可用**。

## 7. P0 实测小结（2026-09-05，几何证据层）

在 3 份报告（茅台 110 / 移动 214 / 平安 370 页，后两者 A+H 年报）上用 pdfplumber/pdfminer 完成几何层实测，
详见 [engines-probe.md](engines-probe.md)。要点：

- 字符/词级坐标可靠（无 `(0,0)` 塌缩）；页眉页脚可按坐标+跨页重复分类；“合计”等表内词不会被误删
  （茅台 169 / 移动 135 / 平安 190 次，页眉页脚均为 0）。
- 页眉模板：茅台 1、移动 1、平安 **12 个章节型模板** → 必须“模板分组 + 坐标分类”，不能假设单一模板。
- A+H 特有难点：平安 15 混排页+2 英文页、装饰镜像文字（p5 `们我于关`＝“关于我们”镜像）应按装饰对象分类而非当乱码。
- **无框线高数字页：茅台 0%、移动 17%、平安 40%** —— pdfplumber 框线表检测不足以支撑主路线。
- **MinerU pipeline 对照（已跑，平安 p14–15、移动 p126）**：无框线主表恢复为结构表且数字正确、移动附注表
  `rowspan/colspan` 多级表头保留；但有伪影（空行/杂散 token/合并拍平）→ 只能作“结构候选”，须进统一结构 +
  适配 + 质量门，不能把其 markdown 当权威。
- **主引擎分工（已由实测支持）**：pdfplumber=几何证据/页眉/阅读顺序/有框线表；
  **MinerU pipeline=无框线表/多级表头结构候选**；Docling/PP-StructureV3=繁体/扫描对照补充。
- 复现：`python3 scripts/p0_probe.py <pdf> --pages 2,5,8,26 --full`；
  MinerU 单页：`mineru -p <pdf> -o <out> -b pipeline -m auto -s <p0> -e <p1> -l ch`
