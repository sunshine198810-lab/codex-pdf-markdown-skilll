# V0.3-C4.4 异常文字层与数值证据恢复（2026-09-06）

## 目标与不可越过的边界

C4.4 处理三种在 C4.3 暴露的结构缺口：PDF 可见数字不在文字层、中国人寿资产负债表题日期数字缺失、中国太保 MinerU 合并单元格把四列 HTML 膨胀为十余列。本轮没有把 OCR/MinerU 数字直接写入 facts，也没有添加公司名、证券代码或页码特判。

## 中国人保：矢量轮廓数字证据链

中国人保主表页 127–138 的中文科目和表题是文字对象，但数字字符计数为 0；页面没有嵌入栅格图，存在数百个 curve/path 对象。源页渲染可见数字，PDF 内容流检查也观察到大量路径绘制操作，因此判定为“矢量轮廓数字疑似”，而不是普通乱码字体。

新增 `pipeline/vector_evidence.py`：

1. 只在法定主表标题存在、原生数字字符为 0、曲线对象不少于 50、MinerU 给出二维表且至少两个数值候选时触发。
2. 生成 `复核/vector-outline-index.json/.html` 和逐片段源 PDF 裁图。
3. 按表题分组为六张视觉主表候选；每个 OCR 单元格均标记 `ocr_only`、`no_native_numeric_evidence`、`eligible_for_calculation=false`。
4. 复核队列按六张法定主表登记高优先级任务。候选不写入 `表格/index.json` 的受支持逻辑表，也不写入 `数据/candidates.jsonl` 或 `facts.jsonl`。

结果：中国人保形成 9 个物理片段、6 张视觉主表候选、0 facts，426/426 个 Schema 检查通过。MinerU 已观察到合并行、粘连数字和错列，单一 OCR 输出不足以升级为事实。

## 中国人寿与中国太保

- 中国人寿：资产负债表页的日期数字同样不在文字层，标题只剩“年月日合并/公司资产负债表”。新增受限日期壳规范化：删除完整日期壳后仍须精确命中法定表题。对物理页 89–102 重新做一次 14 页有界 MinerU 切片，最终六类法定主表齐全，另有一张权益表；0 facts，因为期间/行标签等完整事实门仍未通过。395/395 Schema 检查通过。
- 中国太保：MinerU HTML 因 colspan 展开为 14 列，但原生页存在明确“项目或资产/附注/两个日期”四列几何。取消“HTML 仅限 0、3–7 列”的前置拒绝，改为最多 64 列候选均可尝试；最终仍须通过双期间原生表头和严格四列重建。公司资产负债表被恢复，六类主表齐全，facts 由 219 增至 328；478/478 Schema 检查通过。

## 回归结论

`v03-c44-regression-matrix-2026-09-06.json/.md` 固定 13 份报告、10 个发行人：安全门 13/13，总 facts 4,401；11 份产出 facts、1 份仅结构、1 份仅视觉复核。中国人保虽然没有受支持逻辑表，但新增六张可定位、可目检的视觉候选，不能把它误记为结构化成功。

本轮证明的是：对已观察到的三种版式，系统能更早识别异常、恢复可安全恢复的原生结构，并把不能验证的 OCR 数字隔离。它不是保险行业准确率或覆盖率声明。下一步应增加第二独立识别通道、逐格一致性判定与人工签核记录；在这些门完成前，矢量轮廓数值仍不可引用或计算。
